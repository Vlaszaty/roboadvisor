## Rules for parallel lanes

- Branch per lane from `phase0-contracts`: `lane/a-data`, `lane/b-returns-risk`, … (or a git worktree per lane).
- A lane edits only the files it owns (ownership table in the Phase 0 plan). Tests go in the lane's own test directory.
- Contract files (`config.py` structure, `engine/types.py`, `engine/errors.py`, `api/schemas.py`, `data/schema.sql`, stub signatures, route signatures, `tokens.css`) are frozen. If a lane needs a change, it stops and escalates to the integrator; the integrator changes the contract on main and every lane rebases.
- Lanes never depend on another lane's implementation: engine lanes test against `tests/fixtures/synthetic.py`, frontend lanes against `src/mocks` (`npm run dev:mock`). Lane E monkeypatches metrics until Lane D is merged.
- Merge order into main is free (no file overlap); run `uv run pytest` and `npm test && npm run typecheck` after each merge.
- Subagents run on sonnet by default; the math-heavy lanes (C, D, E) and Phase 2 on a stronger model.
